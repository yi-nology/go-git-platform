# v1.0 就绪评估(2026-09-15)

> **决策(2026-09-20):暂不发布 1.0**,继续 0.x 节奏演进。本文档保留作为
> 未来启动 v1.0 时的检查单;其中的工程补齐项(版本化契约、能力巡检示例)
> 已提前落地,不受发布时机影响。

结论先行:**v0.62.0 之后,项目已满足发 v1.0 的全部硬条件**;建议把 v1.0 作为
一个"承诺版本"单独发布(不带新能力),发布动作本身即是向生态声明稳定性契约。

## 一、有利条件

1. **接口面已稳定两个大版本周期**(v0.52.0→v0.61.0,10 个版本):
   8 个核心子接口 + 13 个可选能力接口的形态没有变过;唯一的外形变化都是
   "新增可选能力"(Notification/Reaction/BranchProtection/Collaborator/
   DeployKey/RepoStats/UserManager),没有动过既有方法签名。
2. **行为由机器锁定**:契约测试(基于 httptest 假服务端,逐能力子套件)
   双向锁定"CapabilitySet 声明 ↔ 实现 ↔ 分歧台账"三者一致;分页完整性、
   错误分类、webhook 签名、context 取消均有断言。v0.62 的 go-github v72→v91
   迁移零 fixture 变更通过全部 65 个子测试,是"行为面稳定"的直接证据。
3. **错误模型完整**:10 个 sentinel + `ProviderError`(HTTP 状态码、平台、
   操作、原因),`errors.Is/As` 全支持——这是 go-scm 系挂了 7 年没做的事。
4. **依赖已追平**(v0.62.0):go-github v91、GitLab client-go v3.9.0、
   gitea.dev/sdk v1.2.0、Forgejo v3.0.0、go-gitcode v0.7.2,没有已知 CVE
   钉子。
5. **破坏性预算已经预演**:Gitee SDK 整体替换(v0.54)、Gitea SDK v1 迁移
   (v0.62)都做到下游零感知(统一接口未变)。

## 二、发 v1.0 前需要补齐的工程项(建议随 v1.0 一并交付)

1. **版本化承诺文档** ✅(2026-10-02 已落地):语义化版本下的"什么算
   breaking"(统一类型加字段=非 breaking;接口加方法=对实现者 breaking;
   新增可选能力=非 breaking)已写入 CONTRIBUTING"Versioning &
   compatibility commitment"一节,v0.72/v0.73 的变更记录按此口径执行。
2. **已知限制收口**:分歧台账的 mapping/ignore 项在 v1.0 release notes 里
   显式列出(Gitee 无 Review/CommitStatus 读面差异、里程碑 ID 不可跨平台
   移植、CR number 已 string 化等)。
3. **文档站/示例补齐** ✅(2026-11-04 收口;2026-11-12 计数同步):examples/capabilities
   巡检覆盖 CapabilitySet 全部 23 个能力(声明打印 + 16 个可只读探针;Migrations
   为 ID 级 GetMigration 探针;TeamReviews 为纯写仅声明打印)——比「每个能力
   一个独立 example」更收敛的形态,后续新增能力只需在巡检里加探针。
4. **测试矩阵** ✅(2026-11-12 收口,issue #119):env-gated 真实环境冒烟
   测试已落地——`smoke/` 包,`GIT_PLATFORM_SMOKE_TOKEN` 存在才跑(GetRepo +
   ListRepos 只读两连),未设置时 `t.Skip`;Actions `workflow_dispatch`
   手动触发(smoke.yml,platform/owner/repo 为输入,token 走 secrets)。
   触发方式见 README「Real-environment smoke test」一节。

## 三、遗留限制(发 v1.0 时如实声明,非阻塞)

- Forgejo SDK 不接收 context(mvdkleijn v3 现状,上游无官方 SDK);
- 腾讯工蜂部分字段缺失(Label.ID 恒 0 等,见台账);
- GitLab/Tencent 的 Review 是 approvals 映射合成,非一等评审对象。

## 四、建议

- **v0.62.x 先行**:把本轮改动(依赖追平 + ListCommitStatuses 读面 +
  wait/batch/projection + mcp 模块 + gitbackend 加固)以 0.x 节奏发一个
  中版本,观察 1-2 周无回归。
- **v1.0.0 随后单独发**:内容=版本化承诺 + 已知限制声明 + 文档补齐,
  不塞新能力。发版后接口加方法需走 minor,行为修复走 patch。
